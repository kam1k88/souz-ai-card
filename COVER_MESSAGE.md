Тестовое задание выполнено. Репозиторий: https://github.com/kam1k88/souz-ai-card

**Что реализовано.** CLI-сервис на Python: принимает JSON с данными товара (или забирает товар из вашего фида по id), отправляет его в LLM (по умолчанию локальная модель через Ollama; также поддержаны Anthropic и OpenAI. Для демонстрации использовалась бесплатная модель `openai/gpt-oss-120b` через API Groq) и формирует черновик карточки: SEO-заголовок (≤ 70 симв.), SEO-описание (800–1200 симв.), таблицу характеристик, 3–5 поисковых запросов и commercial-блок для менеджера. Результат сохраняется в JSON и Markdown. Для примеров взял два товара: «Манометр показывающий DM 02» (полные данные) и «Термометр биметаллический ТБ-100» (неполные данные для демонстрации обработки пропусков). Результаты генерации лежат в папке `out/`.

**Ключевые решения.**
- Против выдуманных характеристик: жёсткий промпт + таблица характеристик собирается кодом напрямую из входа (модель её не пишет) + пост-проверка, которая ищет в текстах числа, которых нет во входных данных. Отсутствующие значения помечаются «данных нет».
- Длины и формат ответа проверяются кодом, при нарушении делается повторный запрос с указанием, что исправить (до 3 попыток).
- Некорректный JSON, пустые поля и сбои API обрабатываются отдельно, понятные сообщения и коды возврата. Работа без сети покрыта тестами (`python -m unittest discover -s tests`).

**Сложности.** Модели ошибаются в подсчёте символов, поэтому длину контролирует код, а не промпт. Ещё сложность в проверке фактов: простая проверка чисел не понимает пересчёт единиц.
